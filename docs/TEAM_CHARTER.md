# Team charter — proposed

**Contributors:** Gerald Akorli, Daniel Cardona, Dare Akinpelu.

## Shared norms

1. Each task has one primary owner and a different reviewer.
2. Each working pull request links a tracked issue and includes acceptance evidence.
3. Do not push credentials, real patient data, or unreviewed private datasets.
4. Sync at least twice per week. Record attendees, decisions, assignments and contribution/sign-off status.
5. Escalate blocked work in the same sprint. Owners are accountable for handoffs, not just code.
6. All three members participate in each required project presentation.

## Git workflow

- Branch name: `task/<TASK-ID>-short-description`
- One issue per task with a verifiable deliverable and acceptance criteria.
- At least one peer review for any merge that changes application behavior or database schema.
- Merge only after tests and documented checks pass.

## Course alignment

Follow CISC 520 Project Guidelines. Each phase report needs cover, submission letter, executive summary, table of contents and instructor-prescribed sections. Phases I and II presentations are at most 20 minutes; Phase III at most 45 minutes.
